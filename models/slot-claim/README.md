# Slot claim model (bin/spawn slot claim)

TLA+ model of the worker-pool slot claim: per-slot dir claimed with `mkdir`, a
per-slot lock that is a symlink naming its owner, a stale reclaim with a pid
fence, and a CAP recount before a claim returns success.

Code under test: `bin/spawn:280-393` at `65810a9` (`slot_live`, `slot_lock`,
`claim`). The pre-fix order (mkdir, then lock, then pid) is kept as
`SlotClaim.tla` at `ee31498^`: it is the finding the live replay reproduces.
`SlotClaimLockFirst.tla` is the current order.

## Promises

| # | Promise, one sentence | INVARIANT |
|---|---|---|
| I1 | No two live spawners both believe they hold the same slot. | `NoDoubleHold` |
| I2 | When a claim returns success the live slots are at most CAP, including a CAP lowered while a higher-numbered slot is live. | `HeldCap` |
| I3 | A reclaimer never removes a slot whose owner is live (the pid fence). | `HoldersHaveSlot` |

`HeldCap` counts slots a live actor believes it holds plus the pre-lowering
slot. The stricter `LiveCap` (`LiveCount <= Cap`) is **false by design**
between the pid write at `:369` and the recount at `:371-373`: a fresh dir
briefly makes the live-dir count CAP+1. Every other claimer counts that dir and
blocks, so no claim returns success over CAP. No config checks `LiveCap`.

## Files

- `SlotClaim.tla` - pre-fix order, worst-case timing (the 1s sleep at `:340` is
  a timer, so it is not a bound). Finds the mkdir -> lock gap.
- `SlotClaimTimed.tla` - pre-fix order, intended timing: the 1s grace holds.
- `SlotClaimNoFence.tla`, `SlotClaimNoLock.tla`, `SlotClaimNoRecount.tla`,
  `SlotClaimNoLiveness.tla` - broken copies generated by `gen-variants.py`.
- `SlotClaimLockFirst.tla` - the current order (lock before mkdir).
- `SlotClaimChart.tla` - chart-only projection of `SlotClaimTimed` (2 actors,
  no pre-lowering slot).
- `*.cfg` - one config per run below; `only-*` name a single rule.
- `run.sh` - generates nothing, runs the matrix, compares each verdict.
- `replay.sh`, `claimant.sh`, `slot-lib.sh` - live replay; `extract-slot-lib.sh`
  re-extracts `slot_live`, `slot_lock` and `claim` verbatim from `bin/spawn`.

## The finding and the live replay

In the pre-fix order, A's `mkdir` succeeds, then A stalls past the 1s grace
before the lock; B reclaims the empty dir (`:379-388`), and A and C later each
write a pid into a recreated dir. The empty-pid fence compare at `:385` passes
because `cat` of a missing fence file also prints empty.

`replay.sh` drives the extracted real functions (`slot-lib.sh`), one action per
step; the only injection is a `mkdir` wrapper that sleeps 2.5s after a
successful mkdir. From this directory:

```sh
bash replay.sh plain     # cap 2, three claimants, no stall: no double hold
bash replay.sh stalled   # 2.5s mkdir stall: no double hold on the fixed code
bash extract-slot-lib.sh > slot-lib.sh   # refresh after bin/spawn changes
```

Break test: with `slot-lib.sh` extracted from the pre-fix tree
(`git show ee31498^:bin/spawn`), `replay.sh stalled` prints
`DOUBLE-HOLD slot(s): 1` and exits 1. The repo guard for the fixed order is
`tests/spawn-slot-stall.test.sh`.

## What the timing exclusions leave out

- The 1s sleep at `:381` for a missing pid: `SlotClaim.tla` treats the stall as
  unbounded, `SlotClaimTimed.tla` assumes every live claimant writes its pid
  within the grace. The bug is exactly that gap.
- Pid reuse and `ps -o lstart` granularity: `alive[a]` is "pid alive and start
  matches"; a reused pid with a different start is not modelled.
- `kill -9` of spawn while its worker runs: `slot_live`'s `wpid` branch is
  folded into "owner alive"; the launch window before `:618` is not modelled.
- The legacy directory-lock branch of `slot_lock` (`:293`) and the non-atomic
  read-rm-create of a lock: the lock is one atomic take/steal.
- Claim-scan order: any slot in 1..CAP may be tried at any time.
- A lowered CAP: the model uses one CAP plus a pre-existing higher slot.
